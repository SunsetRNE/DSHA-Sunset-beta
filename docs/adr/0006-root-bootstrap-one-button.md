# ADR 0006：Root 自举一键化与防误操作

状态：**基础 UI 已实施；F01/F04/F07/F08 已按[修复交接计划](../audits/root-adb-bringup-20261009/remediation-plan-20261011.md)实施（2026-10-11 第二轮，软件通过）。** 控制器级并发用例与界面仪器验收仍未交付，见该计划 §7 剩余范围；本文档更新不代表设备验收已完成。历史工程包 `install-178-onebutton.apk`。相关：[ADR 0005 ADB 全局授权单一入口](0005-adb-global-authorization.md)、[Root ADB 自举审计](../audits/root-adb-bringup-20261009/README.md)。

## 1. 问题

自举页把**六个动作**（授权公钥 / 收窄双栈 / 开启监听 / 关闭监听 / 撤销公钥 / 只读刷新）与
**一键自举**平铺在一起，仍然要求用户：

1. 先去 Root 授权页开「允许 Root Shell」；
2. 再回本页打开「允许 Root 自举 ADB」（第二个开关）；
3. 才敢点「一键自举」；
4. 同时还要在一堆同等权重的按钮里判断哪个是"正常流程"、哪个是"清理动作"。

结果是**用户会乱操作**：可能单独点了"撤销本应用公钥"或"关闭 ADB 监听"，把已经建立的授权拆掉；
也可能在缺少前置条件时反复点一键自举，只得到一句 toast。

## 2. 决策

### 2.1 一个主按钮

页面上只保留**一个**常规按钮：

```
[ 一键完成 Root 自举 ]      ← 点它：先自动只读刷新状态，再按需处理前置条件，最后跑完流程
```

一次点击的用户可见目标：**只读刷新 → 前置条件检查 → 一次确认 → 授权公钥 → 收窄双栈 → 开启监听 → 会话核验**。原生 AUTHORIZE 内部已经先做双栈防护，不能把这里的动作名称理解成先裸写公钥。

当前控制器在原生 OPEN 成功后、会话核验前先开启本应用 ADB 通道，以取得强制 ADB 执行计划；核验成功才应显示整链完成。此时序及尚存的“覆盖用户撤销”“最后一步未提交却启用”问题见交接计划阶段 B。失败即停、不重试、不换通道是目标约束，不能因队列为空或前一步成功而视为已满足。

「只读刷新状态」不再单独占一个按钮（收进这一步，排障时可在「高级操作」里单独执行）。

### 2.2 前置条件由程序处理，不让用户记

点主按钮时按顺序自动判断：

| 情况 | 程序行为 |
|---|---|
| 未开「允许 Root Shell」 | 弹窗说明 → 给一个按钮直达 **Root 授权页**（本页不偷偷开） |
| 未开「允许 Root 自举 ADB」 | 在**同一次确认**里问清并开启，确认后**直接继续跑链**（不再让用户点第二次） |
| 上次结果未知 | 提示先「只读刷新状态」，不自动重放 |
| 系统无线调试在跑 | 主按钮禁用并显示原因 + 「打开开发者选项」入口（改设置仍由用户确认） |
| 已有任务在跑 | 主按钮显示当前步骤，禁止重复提交 |

### 2.3 危险动作收进「高级操作」

单独执行与清理动作（授权公钥 / 收窄 / 开启 / 关闭监听 / 撤销公钥）折叠进
**默认收起**的「高级操作」区域，展开后才出现，且每一个仍走原有的**逐次确认**与原生门禁。
折叠只是降低误触面，**不放宽**任何原生授权、代次核验或短期待授权。

### 2.4 状态文案要能回答"现在到哪了"

- 主按钮进行中显示「正在执行：<当前步骤>…」；
- 结果区保留上次观测值、公钥 / 监听 / 双栈三行与失败原文入口（原有设计不变）；
- 「关闭 ADB 监听」「撤销本应用公钥」等清理动作在高级区里**各自**说明"不会自动清理"的后果
  （沿用既有 cleanup 文案）。

## 3. 安全不变式（一键化不得放松）

1. **原生门禁不变**：[请求策略](../../app/src/main/java/com/deepseekharness/app/util/AdbBootstrapPolicy.java)与[短期授权代理](../../app/src/main/java/com/deepseekharness/app/RootBootstrapAuthority.java)的固定动作、120s、进程存活、APK 身份和实际授权回查继续生效；一键只合并用户确认，不跳过门禁。
2. **失败即停**：任一步失败保留现场，不重试、不换通道、不自动重放。
3. **独立授权仍然独立**：`adb_bootstrap` 仍是独立开关、独立代次；自动开启必须经用户确认，
   关闭它不会删除已有公钥或关闭端口（清理仍需显式执行）。
4. **不改命令策略**：`[POLICY_BLOCKED]` / `[EXECUTION_UNKNOWN]` 语义与退出码不变。
5. **root 开关不在本页**：本页只提供跳转，不代开 `allow_root_shell`。

## 4. 历史影响面

build178 的一键化改动限于界面和布局。这个历史范围不约束后续修复；控制器、原生协议或探活的变更须按[当前受管输入清单](../../app/src/main/assets/managed-runtime-inputs.json)判断运行时身份影响。

## 5. 已知遗留与后续实施

当前单次会话核验失败不能只归因于公钥生效慢，事实与方案范围见[修订后的 ADR 0007](0007-bootstrap-session-verification.md)。固定 2.5 秒等待与用户显式只读再核验已有实现；本次计划先解决确定的授权、事务、续链、互斥和界面缺陷，不默认加入自动重试或额外重启。

关闭独立自举开关仍不自动撤钥或关闭监听；高级清理动作单独确认。无操作 REVOKE 是否还留下其他未决事务，必须按交接计划 F03 独立表达。

## 6. 验收

1. 主按钮：在"未开自举授权"的状态下点击，一次确认后能自动继续跑链（不要求第二次点击）。
2. 未开 Root Shell 时，主按钮给出直达 Root 授权页的入口。
3. 高级操作默认不可见；展开后才出现，且每个动作仍要求逐次确认。
4. 无线调试在跑时主按钮禁用并显示原因。
5. 既有策略测试继续通过，并新增能击中旧错误的行为回归：任务中撤销/关闭再开启、最后一步提交拒绝、结果持久化失败、核验途中返回或旋转、子页面改变授权后返回首页。完整矩阵与验证分层见[修复交接计划](../audits/root-adb-bringup-20261009/remediation-plan-20261011.md)。
