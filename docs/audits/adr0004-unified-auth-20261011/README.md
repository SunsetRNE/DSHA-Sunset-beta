## 观察结果

在设置 → 设备能力授权页看到的是**一张授权卡 + 来源分节**，与 ADR §3.3 的树一致：

```
设备命令授权
├─ 已授权 · 来源=Root（uid 0） · 可用于：设备 shell（短信查询仍需单独授权）
├─ Root shell：已授权
│  Shizuku：可授权（尚未授权 DSHA）
│  ADB 自举：被阻塞（系统无线调试占用中，自举按设计拒绝接管）
│  无线调试：等待完成（尚未观测）
│  USB 调试：已授权
│  虚拟屏：未开启（尚未观测）
│  无线调试自动恢复凭据：被阻塞（自举期间禁止自动重开无线调试）
├─ ① App 自举（推荐，免配对）
├─ ② 系统调试授权 ← 只读检测：系统调试授权已开启（无法区分 USB 与无线调试）
├─ ③ Root（独立权威）
└─ ④ Shizuku（中间层：来源 = ADB / Root）
```

要点核对：

| ADR 要求 | 实测 | 结论 |
|---|---|---|
| 权威唯一、UI 显示来源 | 总结行「已授权 · 来源=Root（uid 0）」 | ✅ |
| 每条管道给阻塞原因而非布尔 | 7 行管道状态，括号内均为具体原因 | ✅ |
| USB 调试只读探测、不美化 | 「只读检测：系统调试授权已开启（无法区分 USB 与无线调试）」 | ✅ |
| Shizuku 标为中间层 | 「中间层 · 由 Root 启动，不是授权本身」 | ✅ |
| 短信与设备命令授权分离 | 短信仍在「独立敏感能力」节，授权卡内明确「短信查询仍需单独授权」 | ✅ |
| 自举卡升到首位且为推荐路径 | ① 位于四节之首，标题「App 自举（推荐，免配对）」 | ✅ |
| 撤销立即生效、不自动重连 | 关掉「允许 Root Shell」后 1 秒内总结变为「未授权 · 没有可用的设备通道」；再打开恢复为 Root | ✅ |
| 状态只从证据重算 | 撤销后 ADB 自举原因从「无线调试占用」变为「自举需要 Root」，Shizuku 来源变为「尚未观测到启动来源」 | ✅ |

  「未取得」表述与阻塞原因是否正确。
