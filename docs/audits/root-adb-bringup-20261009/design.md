# Root 自举 ADB：原生实现契约

本轮经用户明确确认实现了原生命名入口、独立授权、五个写动作及原生 UI。实现和验证说明见 [本轮交付记录](implementation-20261010.md)。本文描述源码契约，不表示当前设备已经启用，也不提供持久模块或 chroot 运行时。

## 授权与入口

原生授权默认关闭，独立保存在设备授权偏好中，不随便携设置、系统备份或用户归档恢复。设备授权页先审阅独立授权，再逐次确认动作；页面退出、旋转和语言切换不会重放动作。

命名请求为 `adb-bootstrap`，固定字段 `operation/action/port/selfPackage/selfUid/authority`。五个写动作只接受小写 `authorize/revoke/narrow/open/close`，另有只读 `status`。端口省略或 0 归一为 5555，仅另接受显式 5555。请求不携带任意路径、属性名、命令串或公钥正文。

特权进程要求真实 UID 0，并由 PackageManager 独立核验当前安装包、UID 与已加载 APK 来源。原生短期代理在任务提交时创建，覆盖客户端准备过程，绑定一次动作、随机票据、真实对端 UID、Android 登记的应用主进程以及授权代次；关闭再开启不能复活旧请求。特权写入前回查。Root、应用主进程与 init 的网络 namespace 必须一致，无法核验时停止。公钥经本机原生代理提供，只来自当前数据根中的客户端公钥文件，不读取私钥。

策略元数据通过不等于原生许可。`DeviceShellPolicy` 保持既有 BLOCK 面，Root → Shizuku → ADB 的发送前选择不变；没有给通用桥路由、插件或 Web 页面增加自举入口。

| 动作 | 当前执行前提 |
|---|---|
| AUTHORIZE | APK 身份、Root/自举许可、公钥验证、共享表快照、双栈防护与监听证据 |
| REVOKE | APK 身份、Root 许可、密钥所有权和事务证据；不依赖自举开关仍开启 |
| NARROW | APK 身份、Root/自举许可、两族工具可用、监听证据、规则顺序 |
| OPEN | APK 身份、Root/自举许可、已授权客户端公钥、双栈防护和监听复核 |
| CLOSE | APK 身份、Root 许可、同一开机代次的监听所有权、关闭及规则所有权证据 |
| STATUS | APK 身份、Root 许可；只读，不建立授权或续做事务 |

「ADB 设备通道」不再作为 AUTHORIZE/OPEN 的门禁。本自举的用途是在尚无 ADB 授权时
**免系统配对**地把它建立起来；若要求通道先行开启，就会形成「要先有 ADB 才能自举 ADB」的
循环，与本文件开头「不经系统配对弹窗即可获得 ADB 通道」的目标相反。
`DeviceBridgeService.isAdbEnabled` 保留其原配对路径的开关语义，并在三步全部成功后由
一键自举自动置为开启。

一键自举在 Java 层按固定顺序串行 `AUTHORIZE → NARROW → OPEN`，复用与单动作完全相同的
门禁、短期票据与结果记录路径；任一步不成功即停止并保留现场，不重试、不换通道。

Root 许可也被撤销时不暗中提权清理。关闭自举开关只阻止后续受控写入，已生效的设备状态必须另行检查和清理。

## 密钥事务

只接受规范的 Android 2048 位 RSA 公钥结构，校验 Base64、模数、指数和 Montgomery 字段。原授权表逐字节保留；授权按公钥身份去重，原已存在的同一把公钥不认领为新增所有权。

事务使用固定 root 私有目录与进程间锁，持久化原件、前后摘要、所有权行和独立的公钥阶段。共享表必须是可信目录内的普通文件，核对链接数、owner/mode/label；同目录临时文件持久化后，在最终授权及原件复核通过时替换。不得自动把整表备份覆盖回当前表。

撤销只删除唯一、精确匹配的所有权行。重复条目、注释/所有权变化或公钥换代不静默归一。外部已经移除本应用公钥时，清理不会重写其它条目。完整固定列表证明 daemon 已停止时，可直接选择性撤销并复核，不要求重新开启 ADB；运行中则以开机代次及 PID/出生身份确认已有服务退出。已发送但结果未知的重启不能再发送一次，公钥重新出现也不能重置发送阶段。

该锁只协调本实现的请求。提交前字节/元数据复核不构成与所有 Android 配对服务或外部 root 写者共享的内核 CAS；设备验收必须测试并发配对，并避免同时通过其它入口修改授权表。失败保留原件和事务证据，不假定无影响。

## 双栈与监听

默认关闭、按需开启。IPv4 与 IPv6 工具及 proc 网络表都须可核验，不能把工具缺失解释为该族不存在。仅本应用记录拥有的规则可以清理；存在同标签而无所有权记录时停止。防护规则须位于 INPUT 第一条，单独一次 `-C` 成功不能证明访问已经收窄。

先核对 service/persist/TLS 配置及实际 daemon socket inode 与双栈网络表，再建立并复核两族防护，最后授权公钥或开启监听。共享公钥会影响其它 adbd 入口，遇到其它端口或无线 TLS 调试就拒绝；外部来源的监听不自动接管。监听开启后复读状态，并通过受管客户端固定连接 `127.0.0.1:5555` 执行只读 `id`；专用验证模式只连接一次，不枚举地址、不走 mDNS/历史回退，不自动申请额外系统权限。客户端会话 UID 与 daemon 身份分别解释，不从一条 UID 推导全部能力。

关闭使用本应用记录和开机代次，将属性写入及重启发送分阶段持久化；未知阶段先观察，不能重发重启。确认 5555 没有监听或存活连接后才删除本应用规则。规则、属性或端口证据不完整时保持未知。属性写入成功不能代替实际监听证据，外部连接超时不能代替本地规则证明。

本轮没有长期 root 守护服务或 KernelSU/Magisk 持久模块；“上次核验”不是持续防护承诺。重启、厂商网络重建和 root 方案变化均需重新验收。

## UI、兼容与失败

应用级控制器只持有 Application，单飞而不排队旧请求。UI 只读取不可变快照，确认绑定快照身份和授权代次；暂停页面即撤去旧确认，销毁 view 时关闭对话框并解绑；恢复只重绘快照，不中断后自动重发。Root/Shizuku 原有验证回调也核对 view 和请求代次。

中英文状态按显示时语言生成，设备原始结果不自动翻译。授权、最后结果、监听、公钥、防护、观测时点和残留清理分别呈现。待核验动作独立于最后请求结果保存，失败/不完整的刷新不解除门禁；未知结果先只读刷新，再选择必要的清理操作。

Low 使用 API 23 可用的进程/文件描述符能力；API 23–25 文件标签采用系统接口适配，API 26+ 使用公开 xattr。接口不可用或标签不一致时停止；不修改 SELinux 规则、不关闭执行保护。各 ROM 的 su、SELinux、iptables、proc 和旧系统接口仍须真机验证。

## 验证分层

纯逻辑与事务判据、Android 源码编译、双 flavor 单测/Release Lint、完整 APK/离线资产/签名、以及设备验收是不同证据。命令和实际结果以 [实现与验证说明](implementation-20261010.md) 为准。缺失归档或使用 AIDL 等价产物的情况必须公开记录，不能扩大为完整发布验收通过。
