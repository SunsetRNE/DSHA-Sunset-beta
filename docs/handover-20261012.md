## 3. 设备实测发现（已写进计划 §7.4）

1. **环境维护门禁过去只在 `MainActivity.onCreate`**：覆盖安装后从文件管理器「打开」、
   任务被恢复到别的页面（例如自举页）都会整段跳过门禁，只有退出重开才触发。
   已修：`ui/EnvironmentGate` 成为唯一判据，`DshaApp` 注册应用级回调，任意非豁免页面回前台先过门禁。
2. **双实例桥不兼容（未做改动，已取证）**：loopback 3090 只能被一个实例持有。
   实机证据：`com.dsh.client`（uid 10304）持有 3090 与 3081 的监听；`com.dsh.clienu.SunsetRNE`
   （uid 10307）在 3000–4000 段**没有任何监听** → 它容器里的 `adb-shell.py` 打到的是别人的桥，
   被 token 校验 fail-closed 拒绝（自举最后一步「会话核验」因此拿不到 ADB 计划）。
   建议方案：桥端口回退（3090→3091→…）+ 容器内 `/root/.dsh/.bridge_port` 发现文件，
   `adb-shell.py` 与 5 个内置插件（`dsh-computer-use-android`、`dsh-tool-vsync`、
   `dsh-status-overlay`、`dsh-task-notifier`、`dsh-device-shell-guide`）与 `bridge-token-compat.cjs`
   都读它。**不要**让一个桥接受另一个实例的 token（TCP loopback 拿不到调用者 UID，
   token 是唯一认证；那等于同机任意能读到 token 的应用都能驱动设备通道）。
3. **SunsetRNE 侧有 10+ 个 `:shizuku` 残留进程**（`ps -A` 可见），未排查。

## 5. 构建 / 验证命令（本环境实测可用）

```bash
# 工具链：JDK17 + SDK 在 /root/Android；python3 3.12；node 24（无需网络）
export ANDROID_SDK_ROOT=/root/Android ANDROID_HOME=/root/Android

# 宿主回归（快，不需要 Android SDK）
python3 -B tools/test-root-support.py              # 137 项
python3 -B tools/test-root-bootstrap-endpoint.py   # 15
python3 -B tools/test-adb-flow.py                  # 29
python3 -B tools/test-native-device-policy.py      # 16
python3 -B tools/test-device-shell-policy.py
python3 -B tools/run-host-tests.py --check-manifest   # PASS_MANIFEST(130)

# 描述符
python3 -B tools/prepare-runtime-descriptor.py --check
python3 -B tools/verify-runtime-descriptor-source.py

# Android 侧（可定向；全量会挂，见下）
bash build.sh :app:testStandardDebugUnitTest --tests 'com.deepseekharness.app.util.AdbBootstrap*'
bash build.sh :app:testLowDebugUnitTest    --tests 'com.deepseekharness.app.util.AdbBootstrap*'
```

**已知环境问题（不是代码问题）**：

- 全量 `:app:testStandardDebugUnitTest` 在本容器卡在既有
  `ManagedRuntimeTransactionTest`（`JvmBackupFileSystem.read` → `LinuxFileStore.getmntent0`，
  CPU 打满且不再产出结果）。因此用「整包编译 + 定向过滤」代替，并在交付里如实标注。
- `AdbWheelPathsTest.externalBindingsForeignHostsAndLinkCyclesNeverCreateCache` 既有失败（环境相关）。
- **Gradle 构建必须串行**：同时/排队中的 Gradle 运行会在测试任务阶段拿到混合编译产物
  （新测试源 + 旧主类），产生假失败 —— 实测一次排在别人后面约 1 小时的运行报了 3 个
  `WirelessReopenPolicyTest` 假失败，串行重跑即 BUILD SUCCESSFUL。改完源码要重新跑时，
  先确认没有别的 Gradle 还在跑。
- **正式发布签名密钥（E7E3）不在本环境**：`assembleStandardRelease` 会被签名门禁阻止。
  本环境只能出 debug 签名的测试包（脚本 `/tmp/build-sunsetrne.sh`：临时改 applicationId →
  `assembleStandardDebug` → 输出 `/tmp/SunsetRNE-v<code>-<HHMM>.apk`；再拷到手机 Download 并写 sha256）。
