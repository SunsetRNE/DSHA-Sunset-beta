## 改了什么

按 ADR 0004 的**阶段 0 + 阶段 1**（都不触碰受管运行时身份）：

- 新增 `util/DeviceAuthorization`（权威 / 凭据 / 管道三类分开；`plan()` 与历史 if 链逐项等价）
  与 `util/ShizukuStatus`（Shizuku 的第一个专属单测）；`ShizukuShell.userStatus` 改为委托。
- 新增 `core/DeviceAuthorizationReader`：设置页与诊断页**共用同一份授权快照**，
  每条管道给出可用性与阻塞原因，而不是布尔。
- 设置页从「四张并列卡」改成「一张授权卡 + 来源分节」：① App 自举（推荐）② 系统调试
  ③ Root ④ Shizuku，并显示总结状态；Shizuku 明确标注为中间层。
- USB 调试按 ADR §6-2 选 (b)：只读探测系统调试开关，措辞明确「无法区分 USB 与无线」。
- `AdbPairActivity` 不再越过 `DeviceBridgeService` 的实例防重入校验直写通道状态。
- 删除 `tools/i18n/messages.json` 的死 key `m0284/m0285/m0286`。

**2 项失败先于本轮存在**（main `8a4e09b` 即红，文件不在本轮改动内，未修）：

- `AdbFirewallToolTest.evidenceNeverCarriesTheReservedProtocolTokens`：`AdbFirewallTool.neutralize()`
  把 `[EXIT=125]` 变成 `(exit=125]`，测试要求 `(exit=125)`。该文件是受管输入，修它会改
  `runtimeId`，留给阶段 2。
- `AdbWheelPathsTest.externalBindingsForeignHostsAndLinkCyclesNeverCreateCache`：软链环用例依赖
  本机 `/tmp` 语义，在本容器不成立。

另修一处**先于本轮存在的测试编译错误**：`AdbFirewallToolTest` 六个方法缺 `throws Exception`，
不修则整个单测任务无法编译。

全量单测（含 `backup/`）在本容器的 FUSE 上会长时间卡在 `JvmBackupFileSystem.stat` →
`Files.getFileStore`，本轮未跑完；未跑完不等于通过。

## 真机验收（虚拟屏，2026-10-11，安装后）

被测包已装入手机并在独立虚拟屏（displayId 6，1008×1792，通道 root）中驱动，验收范围与证据见
[ADR 0004 阶段 0+1 真机验收](../audits/adr0004-unified-auth-20261011/README.md)。

要点：一张授权卡 + 四节来源在真机上成立；总结状态显示「已授权 · 来源=Root（uid 0）」；
七条管道各自带具体阻塞原因；USB 只读检测与 Shizuku「中间层」措辞如实；
关掉「允许 Root Shell」后 1 秒内总结变为「未授权 · 没有可用的设备通道」，重新开启后恢复，
且 ADB 自举原因随之从「无线调试占用」变为「自举需要 Root」—— 状态确实从证据重算，没有缓存结论。
