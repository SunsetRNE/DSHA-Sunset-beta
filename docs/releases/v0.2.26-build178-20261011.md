## 改了什么

**页面只剩两个常规按钮**

```
[ 一键完成 Root 自举 ]   ← 主按钮：一次确认后自动跑 授权公钥 → 收窄双栈 → 开启监听 → 会话核验
[ 只读刷新状态 ]         ← 只读，随时可点
```

**前置条件由程序处理**（用户不再需要记住两个开关）

| 情况 | 行为 |
|---|---|
| 未开「允许 Root Shell」 | 弹窗说明 + 一个按钮**直达 Root 授权页**（本页不代开） |
| 未开「允许 Root 自举 ADB」 | **同一次确认**里问清并开启，确认后**直接继续跑链**（不用点第二次） |
| 上次结果未知 | 提示先「只读刷新状态」，不自动重放 |
| 无线调试在跑 | 主按钮区显示原因 + 「打开开发者选项」入口（改设置仍由用户确认） |
| 有任务在跑 | 主按钮显示「正在执行：<当前步骤>…」并禁用 |

**危险动作收进默认收起的「高级操作」**：授权公钥 / 收窄 / 开启 / 关闭监听 / 撤销公钥。
折叠只降低误触面；每个动作仍走原有的**逐次确认 + 原生门禁**，没有放宽。

**文案**：卡片说明改为「点一键即可自动跑完…；单独执行与清理收在高级操作里，每个动作都会先请你确认」。

## 安全不变式（一键化没放松任何东西）

- 原生门禁不变：ticket / 120s / 进程存活 / APK 身份 / Requirement 集合一个不少；
  一键只是"一次确认后按序提交"，不是"跳过确认"。
- 失败即停：任一步失败保留现场，不重试、不换通道、不自动重放。
- `adb_bootstrap` 仍是独立开关与独立代次；关闭它不会删除已有公钥或关闭端口。
- 本页仍不代开 `allow_root_shell`。

## 已知遗留（写进 ADR 0006 §5，需单独评审）

自举链最后一步「会话核验」按设计**只试一次、不重放**；若密钥表在 adbd 侧尚未即时生效，
首次会停在 `ADB_SESSION_UNVERIFIED`。一键化让用户更容易只点一次，因此这条更值得修，
但修复点在受管文件 `AdbBootstrapController` 且涉及"同端点是否允许受控重试一次"的安全取舍，
**本轮未擅自放宽**，等评审。
