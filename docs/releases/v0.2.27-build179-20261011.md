## 调试结论：用户那次失败的原因

**不是流程 bug，是设计门禁**。设备侧实测（2026-10-11 17:0x）：

| 观测 | 值 |
|---|---|
| `settings get global adb_wifi_enabled` | **1**（系统无线调试仍在运行） |
| 自举卡结果区 | 「请求：授权本应用公钥 / **本次请求被拒绝**」 |
| 公钥 / 监听 / 双栈 | 全部「未知」（没有写入任何东西） |

`RootBootstrapExecutor.verifyListenerScope()` 在 `service.adb.tls.port` / `persist.adb.tls_server.enable`
非空时抛 `Refused("WIRELESS_DEBUG_IN_USE")` —— 无线调试是独立的 ADB TLS 入口，自举按设计**拒绝接管**。
用户是在无线调试仍开着的情况下提交的，于是第一步就被原生拒绝。

**但确实是 UX 缺陷**：build178 的说明写了"无线调试在跑时主按钮禁用并显示原因"，
实际没有实现，导致用户白提交了一次、还留下一条"本次请求被拒绝"的记录。

## 改了什么（ADR 0006 §2.2 修订）

1. **「只读刷新状态」收进一键按钮**：点一键后**先自动做一次只读刷新**（不写设备），拿到新观测
   再决定下一步 —— 不拿旧观测去执行。
2. **无线调试占用在提交前说清**：刷新后若观测到 `WIRELESS_DEBUG_IN_USE`，直接弹窗解释
   「两者互斥、DSHA 拒绝接管也不会替你关」，并给「打开开发者选项」直达；**不再产生失败提交**。
3. **只读刷新按钮移入「高级操作」**（排障时仍可用），主区只剩一个按钮。
4. 缺 Root 授权 / 缺独立自举授权 / 上次结果未知 的处理保持 build178 的行为。

## 仍需用户做的一步

在开发者选项里**关闭「无线调试」**。改这个设置按仓库规矩由用户自己确认，App 只指路、不代改、
也不会在处理期间自动重开。

## 遗留（ADR 0006 §5）

自举链最后一步「会话核验」按设计只试一次、不重放；若密钥表在 adbd 侧尚未即时生效，

涉及"同端点是否允许受控重试一次"的安全取舍，**未擅自改动**，等评审。
