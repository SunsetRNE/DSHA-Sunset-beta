# v0.2.30 / build182（2026-10-11）无码失败不再丢原文 + 环境任务前置检查 · 工程包

回答用户问题「公钥/监听/双栈为什么还是未知」时查出的**两个真问题**，本包修掉。

## 诊断结论

用户截图状态：`请求：授权本应用公钥` · `本次操作失败，请查看详情` · `上次观测：尚未观测` ·
`公钥/监听/双栈：未知` · `REQUEST_OUTCOME_UNKNOWN`。

1. **三个「未知」是观测值，不是"设备上没有"**。它们来自最近一次**成功**的原生回执
   （`keyState/listenerState/guardState`）。这次请求在**发出 root 请求之前**就失败了
   （所以 outcome 是 `FAILED` 而不是 `REFUSED`），从未有过回执 → 三个值一直是「未知」。
   设备侧其实**有**：实测 `/data/misc/adb/adb_keys` 2 行（含 `dsha:com.dsh.clienu.SunsetRNE`）、
   `[::]:5555` LISTEN。
2. **`REQUEST_OUTCOME_UNKNOWN` = 这次失败没有可识别的错误码**：`AdbBootstrapController`
   在异常 message 不匹配 `[A-Z0-9_]{1,96}` 时归为这个码，而旧代码在**该分支把 evidence 丢了**，
   于是卡片既没有原因、也没有「查看失败原文」——**这是诊断盲点**。
3. **触发时机**：用户在 17:21:30 装完 build181（改了受管文件）后 37 秒就点了自举，
   此时**「运行环境维护」仍在切换受管文件**（虚拟屏实测到该 banner）。自举要先准备 ADB 环境，
   环境任务锁被占 → pre-flight 失败 → 无码失败。当时无线调试也仍开着（`1` / `tls.port=34189`）。

## 改了什么

**（a）无码失败不再丢原文**（受管文件 `core/AdbBootstrapController`）：`REQUEST_OUTCOME_UNKNOWN`
分支现在把异常原文（经 `SensitiveData.redact` 脱敏、`AdbFirewallTool.head` 限长）写进 `evidence`
→ 卡片会出现可点的「查看失败原文」。

**（b）环境任务前置检查**（`ui/RootBootstrapCard`，零 `runtimeId` 代价）：点一键自举时先看
`MaintenanceCoordinator.isEnvironmentTaskBusy()`；环境正在维护就直接弹窗说明
「自举要先准备 ADB 环境，而此刻环境正在维护；现在提交只会得到一个无法归因的失败」，
**不再产生一次 REQUEST_OUTCOME_UNKNOWN**。
