# v0.2.32 / build184（2026-10-11）无线调试前置检查改用实时设置 · 工程包

用户报告「Root 自举请求被拒绝了」——查证结论：**无线调试被正式包的 ADB 保活又打开了**，
自举被原生门禁 `WIRELESS_DEBUG_IN_USE` 拒绝；而我的前置检查看的是**快照**，没拦住。

## 诊断证据（设备实测 2026-10-11 20:0x）

| 观测 | 值 |
|---|---|
| `settings get global adb_wifi_enabled` | **1**（用户关过，又变回 1） |
| `getprop service.adb.tls.port` | **41681** |
| `getprop persist.adb.tls_server.enable` | **1** |
| 正式包 `com.dsh.client` 的 `adb_enabled` | **true**（保活总开关开着） |
| 正式包是否持 `WRITE_SECURE_SETTINGS` | 是（此前配对时授予） |

`DeviceBridgeService.tryReopenWirelessDebug()`：探活失败 + 持 `WRITE_SECURE_SETTINGS` →
`Settings.Global.putInt("adb_wifi_enabled", 1)`。它唯一的自我约束是
`AdbBootstrapController.blocksWirelessReopen()`，而那只反映**本包**的自举状态 ——
**同源的另一个包（SunsetRNE 测试包）正在自举，它不知道**。这是"同机装两个同源包"才有的跨包盲区。

原生门禁侧：`RootBootstrapExecutor.verifyListenerScope()` 看到 `service.adb.tls.port` /
`persist.adb.tls_server.enable` 非空即 `Refused("WIRELESS_DEBUG_IN_USE")`（AUTHORIZE 第一步就拒）。

## 我的缺陷

182 的前置拦截读的是 **快照 `detail`**，而该字段只有在**被拒之后**才会写成
`WIRELESS_DEBUG_IN_USE`（STATUS 刷新不做监听范围核验）→ 拦截失效，用户直接吃了一次拒绝。

## 改了什么（零 `runtimeId`）

`ui/RootBootstrapCard`：

- 一键按钮在**提交前**改为读**实时系统设置** `Settings.Global.getInt(cr, "adb_wifi_enabled", 0)`
  （公开只读），开着就直接弹窗 —— 不再依赖滞后的快照；
- 弹窗文案补上根因与解法：「它可能被 ADB 保活自己开回来（同源另一个包也会）。请先关掉那个包的
  ADB 全局授权总开关，再关无线调试。」

## 操作顺序（重要）

1. **先关正式包**（`com.dsh.client`）的「ADB 全局授权」总开关 → 停掉保活；
2. 开发者选项 → 关闭「无线调试」；
3. 装 184 → 打开测试包 → 点「一键完成 Root 自举」。

## 已知边界（记录，不在本轮修）

同机安装两个同源 DSHA 包时，两个包的保活/自举互斥**互不相识**；正式发布只有一个包时，
本包互斥是有效的。跨包协调需要产品层决策（例如检测同源包并在自举期间请求它暂停保活）。
