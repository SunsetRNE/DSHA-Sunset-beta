# v0.2.33 / v0.2.34（build185 / build186，2026-10-11）自举失败原文定位后的两处修复

## 定位结论

**前三步成功、最后一步在本机不可能成功**：

- 授权表内已有 `03:D9:6B:55:85:8D:DB:20 · dsha:com.dsh.clienu.SunsetRNE（本应用）`；
  `service.adb.tcp.port=5555`、`[::]:5555` LISTEN；真 ADB 客户端实测 `id` → `uid=0(root) [EXIT=0]`。
- 最后一步「会话核验」必须跑容器里的 `adb-shell.py --bootstrap-verify`，它要向**本机 3090 桥**
  申请 ADB 计划；而同机装有正式包 `com.dsh.client` 时，3090 属于**启动它的那个实例**
  （本轮就是正式包）→ 测试包的 token 必被拒。
- 这与上一轮审计
  [guard-visibility §真因 4](../audits/root-adb-bringup-20261009/guard-visibility-20261011.md)
  的结论一致：**第二个实例的 ADB 会话核验在本机不可能成功，需要单实例（正式包自己）**。

## build185：我的 bug + 失败原文解释

- **密钥表多出一行**「指纹未知 · 无备注」：设备 shell 输出末尾会附协议标记 `[EXIT=0]`，
  被 `AdbKeyTable` 当成第三把钥匙。已修（跳过 `[...]` 行）并加单测
  `protocolMarkersAreNotKeyRows`。
- **失败原文自动附解释**：当 evidence 命中 `桥拒绝了这个 token` / `DSHA 实例占用着桥` 时，
  弹窗额外说明「这不是自举失败；前三步已执行；只有最后一步需要单实例环境」。

## build186：保活在「结果未知」窗口不得重开无线调试（真缺陷）

链在最后一步以「结果未知」收场后，链里已经把 ADB 通道打开；包的保活随即探活失败，
把用户刚关掉的**无线调试又打开**（实测 `adb_wifi_enabled=1`）→ 下一次自举必然被
`WIRELESS_DEBUG_IN_USE` 拒绝。旧的 `blocksWirelessReopen()` 只拦"正在跑 / 上次正因无线调试被拒"，
**漏了"上次结果未知"这个窗口**。

现在 `unresolved` 也拦停保活，直到用户显式只读刷新（STATUS）把结果确认下来。
这是单实例生产环境同样会中的缺陷，不只是双实例问题。
