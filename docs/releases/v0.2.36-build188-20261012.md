## 改了什么

| 编号 | 变化 |
|---|---|
| F03 | 原生响应新增 `pendingVerified` + `networkPending` / `keyPending`，**所有动作都返回**；宿主只在「可信响应确认两阶段已结束 + 观测完整 + 结果已落盘」时解除未决屏障。旧格式 / 缺字段 / 日志读不到一律保持未知。无操作 REVOKE 不再清除别的未完成事务 |
| F01/F04 | ADB 总开关收敛到唯一受管写入口并记录「用户意图代次」；整链确认只捕获一次，自动启用只在代次未变时提交（被拒报 `ADB_SWITCH_INTENT_CHANGED`，不反转用户开关）；续链改为先 `peek` 再判定，下一步提交失败 / 结果未落盘即终止，不再用「队列为空」推导整链成功 |
| F02/F05 | 开机、覆盖升级与保活共用同一无副作用无线互斥判据（持久保守意图 + 旧数据迁移 + 用户显式切换模式才解除）；保活探活强制 ADB 计划，TCP 快速探活只保留「已经过完整握手」的状态，不再把 Root/Shizuku 成功冒充 ADB 已连接 |
| F06(D1) | 首次写入系统授权表前先做无副作用预检：可信缺失 / 软硬链接 / 元数据 / 标签异常都在**零设备写入**下明确拒绝（如 `ADB_KEY_TABLE_MISSING_UNSUPPORTED`） |
| F07 | 会话核验与授权表读取带请求代次；页面销毁或再次发起使旧回调失效，对话框归属当前页并在销毁时关闭 |
| F08 | 首页每次 `onResume` 从真实存储同步 ADB 总开关，`updating` 抑制监听器，渲染不写回 |

顺带修好既有红灯：`AdbFirewallTool.neutralize` 过去只替换 `[EXIT=` 左半段（留下 `(exit=125]`），
现按完整标记中性化，`AdbFirewallToolTest` 转绿。

## 装这个包会发生什么（重要）

`managed-runtime-inputs.json` 新增了 5 个受管协作者（`AdbSwitch`、`AdbBootstrapReply`、
`AdbBootstrapChainPlan`、`AdbKeyTablePreflight`、`WirelessReopenPolicy`），受管运行时身份因此变化。
**覆盖安装后应用会认为运行环境需要一次维护**：可能出现「环境维护待处理」横幅并跑一次
`RuntimeTrial`，之后才回到正常启动。这不是故障，也不能靠从清单里移出这些文件来回避
（计划 §155 明确要求新增协作者进入受管执行链时纳入清单）。
