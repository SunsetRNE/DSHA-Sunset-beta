# v0.2.37 / build189（2026-10-12）环境维护门禁覆盖所有入口

## 背景：用户实测到的现象

> "覆盖安装之后，用 MT 管理器打开不会触发环境维护，退出之后再打开才会触发环境维护机制，就很神奇。"

## 根因

维护门禁（"必须先进入环境维护页"）过去只写在 [MainActivity.onCreate](../app/src/main/java/com/deepseekharness/app/ui/MainActivity.java) 里，而且只有真正**新建 MainActivity** 才会跑到：

- 全新冷启动 → 新建 MainActivity → 门禁生效 → 进维护页；
- 从任务/最近使用/文件管理器"打开"回到一个**已经存在的任务**，或者系统在进程重建后把栈恢复到别的页面（例如自举授权页）→ `MainActivity.onCreate` 不跑 → 门禁整段跳过；
- build187 补的 `onResume` 探测只把结论渲染成**横幅**（"环境维护待处理 · 点击处理"），不会主动跳转。

实机证据（`dumpsys activity activities`，SunsetRNE 任务 #166）：

```
* Task{... A=10307:com.dsh.clienu.SunsetRNE U=0 sz=3}
  mLastPausedActivity: BootstrapAuthorizationActivity
  * Hist #2: BootstrapAuthorizationActivity
  * Hist #1: AdbAuthorizationActivity
  ...
```

栈顶是自举页、栈里还有授权页 —— 这次进入根本没有经过 MainActivity 的门禁，所以"没触发环境维护"。退出（结束任务）后再打开才是真正的冷启动 → 门禁 → 维护。

安全性不依赖这个跳转：即使某个入口漏过 UI 重定向，Web 启动仍由 `WebLifecycleController` 的同一运行时门禁挡住，旧环境不会被跑起来。缺的是**入口可见性与可达性**。

## 改了什么

- 新增 [ui/EnvironmentGate](../app/src/main/java/com/deepseekharness/app/ui/EnvironmentGate.java)：门禁判据的唯一来源（未决事务 → 未就绪 → 运行身份与 APK 不一致），并带上豁免规则。
- [DshaApp](../app/src/main/java/com/deepseekharness/app/DshaApp.java) 注册应用级 `ActivityLifecycleCallbacks`：任意 Activity 回到前台时先过门禁，成立就把用户送到维护页。
- [MainActivity](../app/src/main/java/com/deepseekharness/app/ui/MainActivity.java) 改用同一个 `EnvironmentGate`，两处判据不会再漂移。
- 豁免（避免与这些流程打架）：维护页 / 欢迎页 / 启动恢复页 / 首次设置（ModelSetup、Onboarding、ColdSetupSpeed）/ 应急 DSH（RecoveryActivity、RecoveryWebActivity）/ 维护相关任务页（NativeData、RetainedData、BackgroundTasks、Update）/ 内嵌 Web 预览与 PiP；带 `limited_entry`、`skip_extract`、`review_only` 的意图同样豁免。
- 用户已经明确选择"受限主界面"（`allowsLimitedEntry`）时不强制跳转，仍走横幅入口。

## 另外两项（F01/F04 的剩余缺口）

- 链状态机抽到 [util/AdbBootstrapChainSession](../app/src/main/java/com/deepseekharness/app/util/AdbBootstrapChainSession.java) 并有主机测试：链内只接受当前步骤、外部动作插不进来、队列取空即结束、意图只捕获一次。
- 每次派发下一步**之前**回查最初确认的总开关意图：用户在步骤之间关掉/重新选择总开关后，旧链不再获得任何新的设备写入，并明确停在 `ADB_SWITCH_INTENT_CHANGED`（卡片有中英文说明），同时立起未决屏障要求先只读刷新。

## 装完应该看到什么（这次的验收点）

1. 覆盖安装 189 后，**无论从哪打开**（MT 管理器"打开"、桌面图标、最近任务、自举页恢复）都应先落到**环境维护页**，而不是直接进主界面。
2. 维护跑完后进入主界面；再退出重开不再需要维护（`attempted_identity` 一次性记录，不会反复跳）。
3. 如果某次打开仍然没有落到维护页，请记下**当时是哪个页面**（例如自举页、终端、Web 预览）——那些豁免页面按设计不跳，但 Web 仍会被挡住；把页面名告诉我，我再收窄豁免范围。
